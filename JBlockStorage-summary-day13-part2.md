### `gui/dialogs/FilePropertiesDialog.java`

Модальное окно по плану из summary-day13.md, шаг 4. Структура:

1. **Заголовок** — «Свойства файла» + имя файла как подзаголовок.
2. **Секция «Общее»** — карточка `props-card` с пятью строками:
   - Загружено (через `FormatUtils.fullDateTime`)
   - Размер (через `humanSize`)
   - Шардов (с правильным склонением через `pluralShards`)
   - Шифрование («AES-256-GCM», константа)
   - ID транзакции — моноширинный обрезанный `shortenTxId`, плюс кнопка «Копировать» с фидбеком (на 1.2с превращается в «Скопировано» и блокируется).
3. **Секция «Хранители»** — карточка с одной строкой на каждого. В строке: `ContactAvatar.SIZE_LARGE` по `storerPublicKey`, имя «Узел XXXXXX» (первые 6 символов ключа) или «Этот узел», моно-ключ через `shortenPubKey`, индикатор онлайн/оффлайн.

Это синхронизировано с тем, как реплики X/Y отображаются в строке таблицы «Мои файлы» — там та же логика (через `Blockchain.findLatestRepairFor` в `MyFilesContentView`).

**Онлайн/оффлайн** — `peerManager().snapshotSessions().get(storerKey)`: если активна сессия → онлайн, иначе оффлайн. Для `selfNodeId` — всегда онлайн (мы сами).

**Окно** — отдельный `Stage` с `StageStyle.UNIFIED`, `Modality.APPLICATION_MODAL`. Body в `ScrollPane`, footer (одна кнопка «Закрыть») всегда виден внизу. CSS подхватываются от `ownerStage.getScene()`. Размеры: 480×автоподгон, минимум 420×360.

Stub-версия по плану из summary-day13.md, шаг 5. Структура:

**Защита от само-расшаривания** — на клик «Поделиться» проверяется, не равен ли введённый ключ `selfNodeId`; если равен — Alert «Это ваш собственный публичный ключ».

2. **Заголовок столбцов** — «Имя | От кого | Размер | _» (последняя «колонка» — пустой Region под кнопку «Скачать»).

Чтобы получить файл, отправьте свой публичный ключ владельцу — его можно скопировать в разделе «Настройки».»

**Источник данных** — `node.listAccessibleFiles()` (возвращает `List<Transaction>` оригинальных UPLOAD-tx, к которым у меня есть ACL). Сортировка по `Transaction::getTimestamp` убыванию.

**Интеграция с DashboardView** — кеширован экземпляр (как и `MyFilesContentView`), при каждом переходе на раздел вызывается `reload()`: `listAccessibleFiles` читает из локального блокчейна, это очень дёшево. Счётчик в sidebar обновляется через `setOnCountChanged` → `sidebar.setCount(Section.SHARED, count > 0 ? count : null)`.

## Решения, принятые в этой итерации

1. **Свежие реплики через `findLatestRepairFor`.** Если был REPAIR — реплики берутся из него, не из UPLOAD. Это даёт честные данные после восстановления (когда узлы-хранители менялись), а не «исторические» из момента загрузки. Ровно та же логика используется при подсчёте X/Y в MyFiles → консистентность гарантирована.

2. **«Этот узел» вместо короткого ID для self.** Самый частый случай при тестировании — пользователь смотрит свойства файла, который сам же и загрузил, и видит свой узел в хранителях. Лучше прямо сказать «Этот узел», чем заставлять сравнивать ключи.

3. **Кратковременный фидбек кнопки «Копировать».** Вместо тостов/popup'ов — текст кнопки на 1.2с меняется на «Скопировано» и блокируется. Меньше движения на экране, проще реализовать (без OverlayHost'а).

4. **Валидация ключа в Share — мягкая, не строгая.** Точная криптопроверка — у бэкенда (`KeyManager.publicKeyFromBase64` + `shareFile`). UI делает только sanity-check (≥200 символов, Base64-алфавит): защита от пустых строк и случайно скопированного email'а, но не от опечаток в реальном ключе. Если ключ некорректный — `node.shareFile(...)` бросит исключение, и пользователь увидит Alert «Не удалось расшарить файл», окно ShareDialog останется открытым для исправления.

5. **Защита от само-расшаривания на UI.** Бэкенд может это и стерпит (создаст ACL, где recipient = owner), но UX явно ошибочный: пользователь зря потратит блокчейн-блок и время. Перехватываем заранее.

6. **Empty state с эмодзи 📥, не SVG.** На macOS (где работает студент и где будет демо) Apple Color Emoji рендерит идеально. На Linux/Windows будет чёрно-белая версия — приемлемо. Можно заменить на SVG-папку в дне 15 (полировка), если потребуется.

7. **Reload расшаренных при каждом переходе.** В отличие от MyFiles, где reload вызывается явно (после upload/share/delete), в SharedFiles новые ACL прилетают извне (через `BlockSyncService` от других узлов). Поэтому проще каждый раз при показе раздела перечитывать `listAccessibleFiles` — операция читает только локальный блокчейн (RAM), стоит микросекунды. На 100 ACL это дешевле любого listener'а.

## Пользовательские флоу, теперь полностью работающие

### Флоу A. Поделиться файлом

1. На «Мои файлы» правый клик по строке → «Расшарить».
2. Открывается отдельное окно «Поделиться файлом» (заголовок macOS с тремя кружочками).
3. Подзаголовок: «{имя файла} · {размер}». Жёлтый warn про «получатель оставит копию», синий info про «попросите ключ из настроек».
4. Пользователь вставляет ключ в textarea (или кликает «Вставить из буфера»). Кнопка «Поделиться» активируется автоматически после ввода ключа правильного формата.
5. Клик «Поделиться» → `node.shareFile(txId, recipientPubKey)` → ACL-запись в блокчейн → broadcast другим узлам.
6. Окно закрывается, появляется Alert «Файл расшарен» с подтверждением.

### Флоу Б. Посмотреть свойства файла

1. На «Мои файлы» правый клик по строке → «Свойства».
2. Открывается отдельное окно «Свойства файла» с двумя секциями.
3. В «Общем» можно скопировать ID транзакции одной кнопкой (с визуальным фидбеком).
4. В «Хранителях» виден список всех узлов, которые держат шарды файла, и текущий статус каждого. Пользователь сразу понимает: 3/3 онлайн → файл точно скачается; 1/3 онлайн → файл скачается, но не сразу; 0/3 онлайн → жди, или просто кто-то будет онлайн позже.

### Флоу В. Скачать файл, который мне расшарили

1. В sidebar клик на «Расшаренные мне» (счётчик показывает количество).
2. Открывается раздел со списком; самые свежие сверху.
3. У каждой строки видно: имя, дата, поделившийся (с цветным аватаром по хешу ключа), размер.
4. Клик «Скачать» → FileChooser → файл скачивается обычным `node.downloadFile`.

## Демо-сценарий ТЗ (3 узла)

В составе архива — `scripts/run-3-nodes.sh`, который открывает три окна
Terminal на macOS и запускает в каждом по узлу:

| Окно | Профиль (нужно создать в GUI первым запуском) | JBS_HOME | JBS_PORT | JBS_SEEDS |
|---|---|---|---|---|
| A | Alice | `~/.jblockstorage-A` | 8081 | — |
| B | Bob   | `~/.jblockstorage-B` | 8082 | `127.0.0.1:8081` |
| C | Carol | `~/.jblockstorage-C` | 8083 | `127.0.0.1:8081,127.0.0.1:8082` |

Это закрывает критерии приёмки из ТЗ п. 8.2.1: одновременный запуск
3 узлов, обмен данными между ними, имитация сбоя через закрытие окна,
проверка целостности через хеш скачанного файла.

Подробная инструкция — в `scripts/README-3-nodes.md`.
